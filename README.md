# persona_generator

[`prompt-composer-static`](https://github.com/sgktmr808/prompt-composer-static) が書き出した生成プロンプト+設定値をまとめて貼り付け、1件ずつ本文と設定を取り出し、生成画像をレビューするiPhone向け関連UI。

生成ルール、キーワードDB、重み、プロンプト生成処理などの本体機能は `prompt-composer-static` 側だけが所有します。このリポジトリは `PCEXPORT` の出力を受け取るUIであり、本体アルゴリズムを含みません。

ビルドステップ無し・依存無し・単一の `index.html` のみ。サーバーサイド処理は無く、貼り付けた内容はブラウザの `localStorage` にのみ保存され、どこにも送信されません。

## 使い方

1. プロンプト生成側アプリで「全件+設定をコピー」ボタンを押す(`<<<PCEXPORT v1 count=N>>>` 形式のテキストがクリップボードにコピーされる)。
2. このツールを開き、貼り付け欄にペーストして「解析する」を押す。ペーストの代わりに「ファイルを開く」から `.md`/`.txt` ファイルを選んで読み込むこともできる(端末内で読み込むだけで、どこにもアップロードされない)。
3. 「前へ」「次へ」(またはスワイプ)で1件ずつ移動し、「本文をコピー」「設定をコピー」でそれぞれ個別にコピーできる。
4. 「画像レビュー」で表示中のプロンプトに発行された生成IDを確認し、そのプロンプトから生成した画像を最大5枚まで登録する。画像を良い順に並べて「この順位で保存して次へ」を押す。プロンプト本文・設定・Seed・画像順位は自動で紐付き、記録はJSONLで書き出せる。
5. 採否・美的満足度・意図一致度・失敗分類・画像メモ・順位の理由は任意で追加できる。画像を別のプロンプトへ自動割り当てする機能はない。

順位は同じ生成IDへ登録した画像内の相対比較であり、採用判断ではありません。1枚だけを登録した場合も順位は1になりますが、不採用評価を付けることも、採否を未入力のまま保存することもできます。

## レビュー方針の世代管理

JSONLにはデータ構造の `schemaVersion` と、質問・尺度・意味を示す `reviewPolicy.version` を別々に保存します。現在の順位は `relative_preference_within_registered_images`、`rankImpliesAdoption` は `false` です。

任意項目は未入力時に `null`、実際に回答した項目は画像ごとの `evaluation.collectedFields` に記録します。後から項目を追加・変更するときはレビュー方針のバージョンを更新し、過去記録の未収集項目を否定評価や0点として扱いません。旧形式の記録は読み込み可能なまま保持します。

前回貼り付けた内容・レビュー結果・登録画像は端末内に保存され、再度開いたときに自動で復元されます。画像本体はIndexedDB、レビュー記録はlocalStorageに保存され、外部へ送信されません。

## フォーマット

```
<<<PCEXPORT v1 count=N>>>
<<<PROMPT 01>>>
(プロンプト本文、複数行可)
<<<SETTINGS 01>>>
(1行のJSON設定値)
<<<PROMPT 02>>>
...
<<<PCEXPORT END>>>
```

## ローカル確認

```bash
python3 -m http.server 8090
```

`http://localhost:8090/` を開く。
