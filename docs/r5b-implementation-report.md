## 0. なぜ項目を増やすのではなく置き換えるのか

既存の合焦ルーブリックは「対象が見えているか / 鮮明か / 前後との差が見えるか」の3段階で、
`present / missing / unclear / target_not_visible` を導出する。この形は**鮮明さを正解として数える**。

意図的な溶解・グリッチ・崩壊を求めるプロンプトでは、鮮明でないことが狙いどおりでありうる。
そこへ3段階の合焦入力を出すと、利用者は「狙いどおりの絵」を失敗側へ記録することになる。

R5B は、宣言したパッケージに限り、それを**1項目の単一選択へ置き換える**。両方は出さない。

## 1. 契約（すべてパッケージ側が持つ）

| キー | 役割 |
|---|---|
| `policy.opticalIntentAlignmentRequired` | `true` のときだけ項目を出す |
| `policy.opticalIntentAlignmentStatuses` | `[{value,label}]`。2つ以上・値は一意・ラベル必須 |
| `policy.opticalIntentAlignmentQuestion` | 画面へ出す設問文（省略時は汎用の既定文） |
| `policy.failureCodeLabels` | 失敗分類の読みやすい短文（保存値は常にコード） |

読み込み時に fail closed で検査する。落ちるのは次のとき。

- 選択肢が配列でない／2つ未満／値が空／値が重複／ラベルが無い
- 設問文が空文字
- **`focusRubricRequired` と同時に宣言している**（同じ判断を二重に尋ねることになる）

拒否しても既存の記録とパッケージは1バイトも変わらない。

## 2. 保存と書き出し

**宣言したパッケージの記録にだけ足す。** 宣言の無い記録へ空文字を入れると、
既存パッケージの `evaluationSha256` が過去の解析JSONと一致しなくなる（R4A で実際に踏んだ回帰）。

- `saveCurrentReview`: `opticalIntentRequired()` かつ値があるときだけ `opticalIntentAlignment` を書く
- `buildReviewRows`: 記録が値を持つときだけ `evaluation.opticalIntentAlignment` を出す
- `normalizedEvaluationOf`: 同様にキーごと出さない

## 3. 未評価のまま提出物を作れる穴を塞いだ

この作業中に見つけた欠陥である。

**書き出しに完成条件が無かった。** 追加ラウンドには「対象が揃うまで書き出さない」ゲートがあったが、
初回ラウンドには何も無く、登録済みの画像が未評価でもレビューJSONLを書き出せた。
書き出したものは提出物として扱われるので、空欄のまま「全件評価済み」として渡ってしまう
（UI品質契約 §9 に反する）。

**画面下部の「未入力 N 件」が合焦入力と狙いとの一致を数えていなかった。**
その2項目だけが空でも 0 件と表示され、保存が通り得た。

いずれも直した。書き出しの前に未評価の画像を数え、残数と場所を画面へ出して断る。

## 4. 検査

新設 `scripts/check_ab_optical_intent.cjs`（実ブラウザ・合成フィクスチャのみ）。

1. 宣言の無いパッケージでは項目も保存キーも増えない
2. 壊れた宣言7種を1つずつ拒否し、そのたびに記録とパッケージが変わらない
3. 設問文と選択肢をパッケージから読む／役割語を画面へ出さない
4. A/B 各2枚 → 1枚目へ入力 → 2枚目へ切替 → 1枚目へ戻して**全値復元**
5. 未入力が1枚残る間は保存も書き出しも通らず、残数が出る
6. ケース移動と再読み込みのあとも全値復元
7. 保存 → 書き出し → 再取込で値・件数・画像ハッシュが一致
8. 押したコピーボタン自身に成功・失敗・再試行が出て、元の文言へ戻る
9. 1280 / 320 / 375 / 390 / 430 / 844×390 で横溢れ0・44px以上・16px以上・A/Bの上端一致
10. 書き出しは使い捨ての保存先に留まり、利用者の Downloads へ0件

`scripts/verify_deployed_r5b.cjs` は公開URLに載った版そのものを同じ順序で通す。

既存2本は新しい遮断規則へ更新した。どちらも「未評価の画像を登録したまま書き出す」ことを
前提にしていたので、**検査の方を書き直した**（R4E の教訓: 検査がブリーフと食い違ったら検査を直す）。

- `check_ab_focus_assessment.cjs`: 未評価画像があると書き出しが断られることを確かめ、
  外してから書き出す
- `check_ab_priority_checks.cjs`: 同上。加えて A/B の枚数と選択位置を揃えてから整列を測る
  （片側だけ未評価だと「未評価画像へ」の案内が片方にしか出ず、整列の実測が実装の崩れではなく
  前提の違いで動いていた）

合成フィクスチャは `scripts/_r5b_fixtures.cjs` で受入検査と公開反映の確認が共有する。
片方だけ古くなって「検査は緑だが公開版は別物」になることを防ぐ。

## 5. 公開の境界

このリポジトリには実験の本文・ID・パッケージ・画像・レビュー・語彙・生成アルゴリズムを1バイトも置かない。
`check_no_experiment_data.cjs` へ R5B 用の検査を追加した。

- 器（宣言キー・同期関数）はある
- **設問文と選択肢を出荷物へ埋め込まない**（実験の分類名が含まれていないことを機械的に確認）
- 3段階の合焦入力との併用を拒否する
- 宣言したパッケージの記録にだけ足す
- 未評価のまま書き出させない
- 失敗分類の短文はパッケージから読む
