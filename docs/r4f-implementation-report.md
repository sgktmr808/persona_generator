**Brief:** `app_static/docs/revisions/r4f-single-task-entry-and-workspace-safety/brief.md`
**Status:** 実装・検査完了。**Codex レビュー待ち**（レビュー通過まで利用者へ画像生成・レビュー再開を案内しない）

## 0. 直した欠陥

公開UIは、利用者が新しい実験を始めるつもりで開いても、**前回開いていた実験を無言で再開**した。
その画面は A/B 両方の「本文をコピー」と複数の画像投入口を同時に出すため、
**どの実験のどの枠へ登録しているのかが画面から分からない**まま画像が登録できてしまった。

| 欠陥 | R4F の是正 |
|---|---|
| 保管庫が端末に1つしか無く、別のパッケージを開くには**既存の記録と画像実体を全部削除**するしかなかった | 実験ごとの保管庫。切替も差し替えも、ほかの保管庫の記録・実体を1件も消さない |
| 再読み込みが、その唯一の保管庫を**無言で再開**した | 開いている実験の身元を画面の先頭に出し、状態を `新規 / 再開 / 生成中 / 評価中 / 完了` で明示する |
| パッケージの切替が「書き出しと管理」の中に隠れていた | 身元パネルに `別の実験を開始・切り替え` を主導線として置いた |
| 案内付き生成中も、旧A/B作業台・両方のコピー・通常の投入口・ケース移動・評価入力が並んでいた | 生成中は**見えていて押せる本文コピー1個・見えていて使える画像入力1個ちょうど**。ほかは隠したうえで無効化し、キーボードと支援技術からも外す |
| 登録の直前に、表示していた対象と保存先が同じであることを誰も確かめていなかった | 保管庫・実験ID・定義ハッシュ・生成ID・本文ハッシュ・端末に保存された定義を再照合し、1つでも違えば受け取らない |
| 削除が通常の切替導線のすぐ隣にあった | 削除は開閉欄の中だけに置き、対象の実験と件数を示して確認を取り、選んだ保管庫だけを消す |

## 1. 実験ワークスペース

- 身元 = `experimentId` + `definitionSha256`。同じ実験IDでも定義が違えば別の保管庫になる
  （古い評価が新しい本文へ紐づかない）。同じパッケージを読み直せば必ず同じ保管庫へ戻る。
- 索引 `personaGenerator.abWorkspaces.v1`、記録 `personaGenerator.abExperiment.v1.ws.<id>`。
- **移行は非破壊・冪等**。R4F 以前の単一保管庫 `personaGenerator.abExperiment.v1` は、
  中身をそのまま新しい鍵へ書き写し、読み直して一致を確かめてから索引を更新する。
  **元のキーは消さない**（移行前へ戻せる控えとして残る）。
  移行の保存に失敗したら作業台を開かず、元の記録はそのまま読める状態で止まる。
- `localStorage.clear()`・データベース全体の削除・オブジェクトストアの一括消去は**使わない**。
- 画像実体の鍵は保管庫ごとに前置する。ただし**移行した保管庫だけは元の鍵のまま**にして、
  既存の画像を1件も書き換えない。別実験の同じ行IDが衝突することはない。

### 1.1 移行前へ戻す手順

移行しても `personaGenerator.abExperiment.v1` は**そのまま残る**。したがって移行前の状態は常に読める。

1. ブラウザの開発者コンソールで `localStorage.getItem("personaGenerator.abExperiment.v1")` を保存する
   （これが移行前のブラウザ内容そのものであり、受入検査でも同じ文字列を控えて突き合わせている）。
2. 移行結果を破棄したいときは `localStorage.removeItem("personaGenerator.abWorkspaces.v1")` と、
   `personaGenerator.abExperiment.v1.ws.` で始まるキーだけを削除する。
   次に開いたときに、残っている移行前のキーからもう一度移行が走る。
3. 画像実体は移行で1件も動かないので、この操作では失われない。

受入検査は、この控えを `pre-r4f-browser-store.json` として書き出し、SHA-256 とともに報告する。

## 2. 入口の3画面

| 画面 | 出るもの | 出ないもの |
|---|---|---|
| 選択 | 保存済み実験の一覧（題名・実験ID・種別・件数）と `再開`、主導線1つ、削除の開閉欄 | 本文・コピー・画像入力・ケース移動・評価入力（**押せるものが0個**） |
| 開始確認 | 題名・実験ID・ケース数・必要枚数・固定の生成条件・進め方・`この実験を開始` | 本文コピー・画像入力（確認を通るまで開かない） |
| 作業台 | 身元パネル（題名・実験ID・種別・進捗・状態・切替）→ 案内カード | 生成中は旧A/B作業台・比較・ケース移動・管理操作 |

`?ab=new-guided` は**汎用の指定**で、実験固有の情報を含まない。この入口では保存済みを1件も操作せず、
選択画面だけを出す。案内付きでないパッケージは
`これは案内付き生成パッケージではありません` と断り、保存済みは変更しない。
実験を明示的に選んだ時点で指定を外し、以後の再読み込みは**その実験**を復元する。

## 3. 生成中の単一導線

生成フェーズで見えていて操作できるのは次だけになる。

- 実験の身元と `画像生成 n / N`
- 今のケース・面・枚数（内部の役割語は出さない）
- 固定の生成条件（読み取り専用）
- `この本文をコピー` **1個**
- 読み取り専用の本文欄（自動コピーが使えないときの受け皿。コピー操作ではない）
- 画像1枚の登録先 **1個**
- 結果の1行と、二次的な開閉欄（別のコピー操作を増やさない）

隠す部品は `hidden` にするだけでなく、`aria-hidden` / `inert` / `tabindex="-1"` と `disabled` を付ける。
検査は「見えていて押せる本文コピーの数」と「見えていて使える画像入力の数」を毎手順で数え、
どちらも 1 であることを機械的に確かめる。

## 4. 登録直前の身元照合

1枚を受け取るときは、画面に出していた対象の身元を控え、**保存の直前と実体保存の直後**に照合し直す。
保管庫・実験ID・定義ハッシュ・生成ID・本文ハッシュ・**端末に保存されている定義**のどれかが違えば、
ファイルはどこにも割り当てず、実体も残さず、手順も進めない。本文は記録された値を信じず取り直して照合する。

## 5. 検査

新設 `scripts/check_ab_workspace_entry.cjs`（実ブラウザ・合成フィクスチャのみ）。

- 画像12件・実体12件を持つ R4F 以前の単一保管庫を仕込み、移行が記録・実体・元のキーを変えないこと
- 読み直しを2回重ねても索引・記録・実体が変わらないこと（冪等）
- `?ab=new-guided` で押せるコピー0個・使える画像入力0個、保存済みは無変更
- 案内付きでないパッケージの拒否、開始確認、旧保管庫の保全
- 全8手順で コピー1個・画像入力1個ちょうど、辿れる操作も同じ2つだけ
- 保管庫の切替・保存済み定義の不一致・本文ハッシュの不一致・保存失敗で登録を断ること
- 旧⇄案内付きの往復で、記録も実体も欠けないこと（鍵の名前空間も確認）
- 移行の保存失敗で閉じ、移行前の記録が読めること
- 1280 / 320 / 375 / 390 / 430 / 844×390 の3画面（選択・確認・生成中）で横溢れ0・44px

既存検査は保管庫対応へ更新した。`check_ab_comparison_workbench.cjs` の回帰フェーズは
「定義変更は削除ではなく別の保管庫」「削除は開いている保管庫だけ」へ書き換え、往復の保全も見る。
`check_ab_r3fb_record_compatibility.cjs` は移行の保全（元キーがバイト同一）を追加した。

`scripts/verify_deployed_r4f.cjs` は公開URLに載った版そのものを実ブラウザで通す
（配信HTMLの版確認 → 旧保管庫の移行 → 案内付き入口 → 1枚登録 → 旧実験へ戻して画像が読めること → 6画面幅）。

### 有界実行

`run_ab_review_release_gate.cjs` は上限時間を**実測から1本ずつ**導く
（`max(実測 x 4, 実測 + 90s)` を10秒単位へ切り上げ）。実行中は心拍（検査名・経過・実測基準・直近の出力）を出し、
心拍そのものは停止の証拠にしない。停止は実測に基づく上限超過で判定する。再試行はしない。
終了後に「実行前後の headless Chrome の差分」で残存プロセスが無いことを確かめ、
残っていればゲートを失敗にする。`check_ab_r3fb_record_compatibility.cjs` が
`process.exit()` を後始末より前に呼んでいて Chrome を残していた欠陥もここで直した。

## 6. 公開の境界

このリポジトリには実験の本文・ID・パッケージ・画像・レビュー・語彙・生成アルゴリズムを1バイトも置かない。
`check_no_experiment_data.cjs` に R4F 用の検査を追加した
（保管庫の切替が全体削除を使わないこと、移行前のキーを消さないこと、
`ab=new-guided` が汎用の指定であること、身元・確認・照合の器があること）。
